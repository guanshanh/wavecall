# 多节点扩容

> **当前状态：客户端已依赖独立调度进程；单节点时在集群表里只配一条 SFU，路径与多节点相同。**  
> **已定：独立调度进程 + 共享静态集群表（`signaling` / `public_ip` / `udp_port`）；客户端始终先问调度再进房。暂不做动态注册。**  
> 名词与职责边界见 [基础概念](concepts.md)。

## 现状

- 每个节点 = 信令 + SFU 同进程；房间整房落在一台机器上。
- 调度与 SFU 共用静态集群表（`cluster.toml`）：调度只用 `signaling`，SFU 用同条目的 `public_ip` / `udp_port` 做 ICE；不是动态注册。
- 房间纯内存：节点挂 → 该节点房间全丢；调度无法恢复内存态。

## 何时加节点

调度器已经是进房必经路径。下面任一情况出现时，再往节点表里加机器：

- 单节点带宽/CPU 到顶（5 人房峰值约 0.83 Mbps 上行）
- 需要排水 / 滚动升级
- 跨机房就近接入

## 架构

```
客户端 ──GET {DISPATCH_URL}/dispatch?room=…──▶ 调度器 cmd/dispatch（:18090，无状态）
       ◀── {"node":"host:port"} ──
客户端 ──WS+RTC──▶ 该 SFU 节点（信令+媒体；ICE = 该节点 public_ip:udp_port）
```

- 调度器：独立二进制，读静态节点表的 `signaling`；对 `roomId` 稳定哈希取模；**不在媒体路径上**。
- 客户端：配置 `VITE_DISPATCH_URL`（必填）；单节点时表里也可只有 1 条，路径与多节点相同。
- SFU：`-cluster-config` + `-node` 读同一份表；协议**不加** `redirect`。
- 断线重连：每次重连前重新问调度，再连返回的 node。

节点表示例：

```toml
[dispatch]
bind = ":18090"

[nodes.n1]
signaling = "n1.wavecall.example.com:18080"
public_ip = "203.0.113.10"
udp_port = 18081

[nodes.n2]
signaling = "n2.wavecall.example.com:18080"
public_ip = "203.0.113.20"
udp_port = 18081
```

加减节点 = 改表 + 滚动重启；约 1/N 房间下次进房/重连会换节点。

## 端口

| 服务 | 端口 | 说明 |
|------|------|------|
| SFU 信令 | TCP 18080 | 每节点 |
| SFU 媒体 | UDP 18081 | 每节点（UDPMux） |
| 调度器 | TCP 18090 | 客户端可达 |

## 边界

- 调度器挂 = 新进房失败；已在房的不受影响（可多实例缓解 SPOF）。
- 静态表无健康感知：死节点仍可能被派到，靠客户端重试。
- 不做跨节点同房、不做房间迁移、第一期不做动态注册/探活/负载调度。

## 演进（接口保持「问调度 → 连 node」）

只改调度器内部：静态表 → 注册 → 健康摘除 → 负载感知。客户端与 SFU 进房流程不变。

## 明确不做

- 跨节点同房间（需节点间媒体转发）
- 用调度「救活」已挂节点上的内存房间
- 房间热迁移（只有重排 + 客户端重进）
